> สถานะ: **ร่างรออนุมัติ** (2026-10-18) — ยังไม่มีโค้ด; เมื่อผู้ใช้อนุมัติจะย้ายกติกาที่ตกลงไป `SPEC.md` แล้วทำตาม Phase P21–P25 ใน `PHASES.md`

## 1. ปัญหาของเกมตอนนี้

| ปัญหา | ผลต่อผู้เล่น |
|---|---|
| รอบเดียวยาว 25–30 วันจำลอง มีเป้าหมายเดียวคือ 100 g | ไม่มีจุดพัก ไม่รู้สึกก้าวหน้า เบื่อกลางทาง |
| ต้องคุมอุปกรณ์ 7 อย่างพร้อมกันตั้งแต่นาทีแรก | ผู้เล่นใหม่/เด็ก ป.5 งงและแพ้ตั้งแต่ต้น |
| กดปั๊มค้างไว้ ผลขึ้นกับ Speed (360x กด 1 วินาที น้ำ +30%) | ควบคุมยาก ไม่ยุติธรรม |
| pH ปรับตรง ๆ ไม่ได้ | ผู้เล่นเห็นค่าแดงแต่ทำอะไรไม่ได้ → หงุดหงิด |
| ถ้าทุกอย่างตั้งไว้ดีแล้ว ไม่มีอะไรเกิดขึ้น | ไม่มีความท้าทาย ไม่ต้องตัดสินใจ |
| ผักเปลี่ยนช้าและละเอียด ต้องเปิดกราฟ | ไม่เห็นชัดว่าผักรู้สึกอย่างไรและเพราะอะไร |
| หน้าจอมีแผง/ตัวเลขเยอะ | ดูไม่รู้ว่าต้องดูอะไรก่อน |

## 2. หลักการออกแบบ (Design Pillars)

1. **เรียนทีละเรื่อง** — ปลดล็อกอุปกรณ์ทีละด่าน (Level) ด่านแรกใช้แค่ 2 ปุ่ม
2. **ทุกการกดมีผลที่เห็นทันที** — ใช้ปุ่มแบบ "ครั้งละ 1 โดส" ผลเท่ากันทุก Speed
3. **ผักพูดได้** — ทุกต้นมีหน้าตา (Mood) และไอคอนบอกสาเหตุว่าผักเป็นอะไร
4. **มีเรื่องให้ตัดสินใจ** — มีเหตุการณ์ (Event) ระหว่างรอบ และมีงบไฟฟ้าจำกัด ทำให้ต้องเลือกระหว่าง "ให้ผักโตเร็ว" กับ "ประหยัด"
5. **ซื่อตรงกับ Simulation** — ทุกอย่างคำนวณใน `sim-core`/Server ภาพแค่แสดง State (ตามกฎใน AGENTS.md); Event และ Level ใช้กลไก Scenario/Disturbance ที่มีอยู่แล้ว

## 3. โครงสร้างเกม: 4 ด่าน + ดาว ⭐

| ด่าน | ชื่อ | ระยะ (วันจำลอง) | เป้าหมาย | อุปกรณ์ที่ผู้เล่นคุม | เหตุการณ์ |
|---|---|---|---|---|---|
| 1 | 🌱 ต้นกล้าแรก | 5 | ผักทุกต้นที่รอดถึง **15 g** | 💡 LED, 🚰 เติมน้ำ | — |
| 2 | 🧪 อาหารของผัก | 8 | ถึง **35 g** | + 🧪 ปุ๋ย | ผักโตเร็ว กินปุ๋ยมาก |
| 3 | 🔥 คลื่นความร้อน | 8 | ถึง **60 g** | + 🌀 พัดลม, 🌫️ หมอก | คลื่นความร้อน 1–2 ครั้ง |
| 4 | 🏆 ฟาร์มของฉัน | 30 (ถึงเก็บเกี่ยว) | **เก็บเกี่ยว 100 g** | ทุกอย่าง + 🫧 ปั๊มลม, ⚗️ pH | สุ่ม 3–4 เหตุการณ์ + งบไฟ |

- เป้าหมาย g เป็นค่าตั้งต้น — **จะปรับจากผล Simulation ใน P21** ให้ผู้เล่นที่ดูแลดีทำได้ทันโดยมีเวลาเหลือราว 20–30%
- **อุปกรณ์ที่ยังไม่ปลดล็อก** ถูกคุมโดย "ผู้ช่วยฟาร์ม" ด้วยกฎคงที่ (เหมือน Ladder ตัวอย่างเฉพาะ Bit นั้น) และแสดงเป็นปุ่มสีเทา 🔒 "ผู้ช่วยดูแลให้" — ไม่นับเป็น Auto/Test
- **ชนะด่าน** = ถึงเป้าหมายภายในเวลา → กด "เก็บเกี่ยว/ผ่านด่าน" · **แพ้** = ผักตายหมด หรือ **หมดเวลา**ก่อนถึงเป้า
- ผ่านด่านแล้วปลดล็อกด่านถัดไป (เก็บใน Memory ของ Lab เหมือน Best; เล่นด่านเดิมซ้ำได้)
- **Free Play / PLC Lab** — โหมดเดิมไม่มีขีดจำกัด สำหรับฝึก Ladder (Auto ยังอยู่ในโหมดนี้เพื่อ Test)

### ดาวต่อด่าน
| ดาว | เงื่อนไข |
|---|---|
| ⭐ | ผ่านด่าน |
| ⭐⭐ | ไม่มีผักตายเลย |
| ⭐⭐⭐ | สุขภาพเฉลี่ยตลอดรอบ ≥ 85% **และ** ใช้ไฟไม่เกินงบ (ด่าน 1–3: งบเผื่อมาก, ด่าน 4: งบตึง) |

คะแนน (Score) ยังคิดแบบเดิม (Care Score + Harvest Bonus) ไว้เทียบ Best; ดาวเป็นเป้าหมายที่เด็กเข้าใจง่ายกว่า

## 4. ความท้าทายระหว่างรอบ

### 4.1 เหตุการณ์ (Events)
มีประกาศเตือนล่วงหน้า **6 ชั่วโมงจำลอง** ("พยากรณ์: พรุ่งนี้บ่ายอากาศร้อนจัด!") ให้ผู้เล่นเตรียมตัว

| Event | ผลใน Model | ผู้เล่นควรทำ |
|---|---|---|
| 🔥 คลื่นความร้อน | Room temp +5 °C 6–8 ชั่วโมง | เปิดพัดลม ลดไฟ LED ช่วงบ่าย |
| 💧 ถังรั่ว | Leak 1.5 L/h (มีอยู่แล้ว: water-shortage) จนกดซ่อม | เติมน้ำบ่อยขึ้น + กดปุ่ม "ซ่อม" (ใช้งบ) |
| ⚡ ไฟดับ | Actuator ทุกตัว OFF 2–3 ชั่วโมง (เหมือน Fail-safe แต่ Air Pump ก็ดับ) | เติมน้ำ/ปุ๋ยให้พอก่อนไฟดับ |
| 🌵 อากาศแห้ง | Room RH −20% | เปิดหมอก |
| 🚿 น้ำประปาด่าง | น้ำเติม pH 8.0 ชั่วคราว | เติมน้ำทีละน้อย ใช้ pH Down |

- Event สุ่มแบบ **Deterministic ตาม Seed + ด่าน** (เล่นซ้ำได้ผลเหมือนเดิม ทดสอบได้) ไม่ใช้ `Math.random`/`Date.now`

### 4.2 งบไฟฟ้า ⚡ (ด่าน 4 เป็นหลัก)
- ใช้ค่า Power (W) ที่มีอยู่แล้ว สะสมเป็น **kWh** → แสดงเป็นแถบ "งบไฟ" บน HUD
- LED 120 W เป็นตัวกินไฟหลัก → ผู้เล่นต้องเลือก: ไฟแรงโตเร็ว vs ประหยัด (ปิดกลางคืน, ไฟ 60–80%)
- เกินงบไม่แพ้ แต่เสียดาวที่ 3 (ไม่ลงโทษหนักเกินสำหรับเด็ก)

## 5. ปรับ Sensor / Actuator

### 5.1 Actuator (สิ่งที่ผู้เล่นกด)
| เดิม | ใหม่ในโหมดเกม | PLC |
|---|---|---|
| Refill Pump ON/OFF ค้าง | **🚰 เติมน้ำ +10%** ต่อ 1 กด (Server เปิด M102 ไว้ 2 นาทีจำลอง แล้วปิดเอง) | Bit เดิม M102 |
| Nutrient A, B แยก 2 ปุ่ม | **🧪 ใส่ปุ๋ย 1 โดส** (A+B พร้อมกัน, EC +≈0.15) | M103+M104 เดิม |
| LED slider 0–100 | **💡 ปิด / อ่อน 50% / แรง 80% / สูงสุด 100%** (Slider ยังอยู่ใน Free Play) | D200 เดิม |
| Fan, Humidifier, Air Pump | ปุ่ม ON/OFF ใหญ่ มีไอคอน+สถานะชัด | M100, M101, M105 เดิม |
| — | **⚗️ pH Down 1 โดส** (ใหม่, pH −≈0.2) | **M106 ใหม่** (ต้องแก้ DEVICE-MAP + allowlist + test) |
| — | **🔧 ซ่อมถังรั่ว** (เฉพาะตอนมี Event) | คำสั่ง Game ไม่ใช่ PLC |

- **โดสไม่ขึ้นกับ Speed:** ระยะเวลาเปิดนับเป็นเวลาจำลองใน Server → แก้ปัญหา "เร่งเวลาแล้วน้ำล้น"
- โดสทำงานเฉพาะ Mock PLC Manual; ต่อ PLC จริง (M3) นักเรียนเขียน Ladder เองเหมือนเดิม
- Gateway ยังห้ามเขียน M Device (FR-31) — โดสเขียนที่ Mock PLC memory ในโหมด Manual เหมือนปุ่มเดิม

### 5.2 Sensor (สิ่งที่ผู้เล่นดู)
- **หน้าเกมแสดง 4 มาตรวัดใหญ่** แบบไฟจราจร: 💧 น้ำ · 🧪 ปุ๋ย (EC) · 🌡️ อากาศ (Temp+RH รวม) · ☀️ แสง
- ⚗️ pH แสดงตั้งแต่ด่าน 4 (เมื่อมี pH Down ให้แก้ได้)
- VPD, DLI, Flow, Water Temp, O₂, Power รายละเอียด → อยู่ในลิ้นชัก "ข้อมูลนักวิทยาศาสตร์ 🔬" (ไม่หาย แค่ไม่รก)
- แต่ละมาตรวัดมี **ลูกศรแนวโน้ม** ↑↓ (จาก History ของ Server) ให้รู้ว่ากำลังดีขึ้นหรือแย่ลง

## 6. พฤติกรรมผักที่เห็นชัด 🥬

| สิ่งที่เห็น | มาจาก State (Server) |
|---|---|
| **หน้า Mood เหนือผักแต่ละต้น** 😄 🙂 😟 😵 💀 | `health`, `damage` |
| **ไอคอนสาเหตุ** 💧 หิวน้ำ · 🧪 หิวปุ๋ย · 🔥 ร้อน/แสงแรง · 🌑 มืด · 🫧 รากหายใจไม่ออก · ⚗️ pH | stress สูงสุดของต้นนั้น (`waterStress`, `nutrientStress`, `lightStress`, `rootHealth`, PPFD ต่ำ) |
| **ป้าย "+2.4 g วันนี้"** ทุกเที่ยงคืนจำลอง | ส่วนต่าง `biomassG` |
| **ฉลองเปลี่ยนระยะ** ต้นกล้า → ใบอ่อน → พร้อมเก็บ (เสียง/แสงสั้น ๆ) | `stage` |
| ใบเหี่ยว ห้อย ม้วน สีซีด/เหลือง/น้ำตาล (มีแล้ว — **เพิ่มความต่างให้ชัดขึ้น**) | `hydration`, `lightStress`, `damage` |
| แถบ Damage สีแดงใต้ต้น (ไม่ลดลง) | `damage` |
| ต้นที่ตาย: สีน้ำตาล ล้ม + ป้าย 💀 | `damage ≥ 1` |

- กฎเลือกไอคอนสาเหตุอยู่ใน `packages/shared` (ฟังก์ชันอ่าน State อย่างเดียว ไม่คำนวณพืช) และมี Unit test
- Animation ทุกอย่างผูกกับ State จาก Server (ไม่มี Animation เล่นเอง)

```
│ เป้าหมาย: ผักถึง 35 g  ███████░░░░ 62%        ⭐ 820 คะแนน  ⚡ งบไฟ ████░ │

│ 🌡️ อากาศ 24° 🟢 │     😄💧   🙂    😟🧪                          │
│ ☀️ แสง 320 🟢   │     🙂     😄    🙂                            │
├──────────────────────────────────────────────────────────────┤

├──────────────────────────────────────────────────────────────┤
│ [💡 แรง ▾] [🚰 เติมน้ำ] [🧪 ใส่ปุ๋ย] [🌀 🔒] [🌫️ 🔒] [🫧 ON]   [📖 คู่มือ] [🔬] │
└──────────────────────────────────────────────────────────────┘
```

- **หน้าจอเกมมีแค่ 5 ส่วน:** แถบบน (ด่าน/เวลา/เป้า/คะแนน) · มาตรวัด 4 ตัว · ฉาก · กล่องข้อความผู้ช่วย · แถบปุ่มอุปกรณ์
- แผงเดิม (Sensors/Trends/Timeline/PLC mode/Scenario) ย้ายไปลิ้นชัก 🔬 — ใช้ต่อในการสอน PLC ได้ครบ
- **หน้าจออื่น:** เลือกด่าน (การ์ด 4 ใบ + ดาว 🔒) · Briefing ก่อนเริ่มด่าน (เป้าหมาย/อุปกรณ์ใหม่/เคล็ดลับ 3 ข้อ) · ผ่านด่าน (ดาว, ผลผลิตรายต้น, "+g", เวลาที่ใช้) · แพ้ (สาเหตุหลักจาก Timeline + "ลองใหม่") · คู่มือ 📖 (เนื้อหาจาก [[GAME-GUIDE]])
- **ผู้ช่วยหยุดเกมให้ (Auto-pause)** เมื่อเกิดเหตุการณ์หรือค่าแดงครั้งแรก — เปิด/ปิดได้ ช่วยเด็กที่ใช้ Speed สูง
- Mobile: มาตรวัดเป็นแถวบน, ปุ่มอุปกรณ์เป็นแถบล่างเลื่อนได้

## 8. แผน Phase (แทน P21–P22 เดิม)

| Phase | งาน | เกณฑ์ผ่านหลัก |
|---|---|---|
| **P21** Levels & Missions (sim-core/server) | นิยามด่านใน Config, ผู้ช่วยคุมอุปกรณ์ที่ล็อก, เป้าหมาย g + เวลาจำกัด, แพ้เมื่อหมดเวลา, ดาว, ปลดล็อกด่าน, kWh/งบไฟ; ปรับเป้าหมาย g ด้วย Simulation | Test: ดูแลตามคู่มือผ่านทุกด่านทันเวลา, ไม่ทำอะไรแพ้, ดาวถูกต้อง, ด่านล็อกบังคับได้ |
| **P22** Dose Actuators (+ pH Down ถ้าอนุมัติ) | คำสั่งโดสนับเวลาจำลอง, LED presets, M106 + DEVICE-MAP/allowlist + Model pH Down | Test: โดสได้ผลเท่ากันที่ 60x และ 3600x, Gateway ไม่เขียน M, pH Down ลด pH ตาม Config |
| **P23** Events & Challenge | Event scheduler (Deterministic), เตือนล่วงหน้า, ซ่อมถัง, Auto-pause | Test: Seed เดิมได้ Event เดิม, ผล Event ต่อ Model ตาม Spec, Pause เมื่อเตือน |
| **P24** Simple Game UI | หน้าเลือกด่าน/Briefing/ผ่าน/แพ้/คู่มือ, HUD 5 ส่วน, ลิ้นชัก 🔬 | Browser จอกว้าง/มือถือ, ไม่มีปุ่มที่กดแล้วไม่ทำงาน (FR-55) |
| **P25** Plant Feedback | Mood + ไอคอนสาเหตุ, "+g วันนี้", ฉลองเปลี่ยนระยะ, เพิ่มความชัดของเหี่ยว/เหลือง/ตาย | Test กฎ Mood/สาเหตุ, ภาพตาม State จาก Server, Browser |

ทุก Phase: แก้ SPEC ก่อนโค้ด → `npm test` + typecheck → docs → commit `phase(Px): ...` → หยุดให้ผู้ใช้ตรวจ

## 9. ไม่ทำ (Out of scope รอบนี้)

- ศัตรูพืช/โรคพืช — ยังไม่มีใน Model พืช ถ้าใส่จะเป็นแค่ภาพที่ไม่ขึ้นกับ Simulation
- เงินในเกม/ร้านค้า — ใช้งบไฟแทนเพื่อให้ผูกกับค่า Power จริง
- Leaderboard ข้ามผู้ใช้/Login (เป็นงาน M4)
- เปลี่ยนสมการการเติบโต — ปรับแค่เป้าหมายด่าน ไม่ปรับ Model ให้ "ง่ายขึ้น"
